# ポケモンカード相場図鑑 設計書

版：0.1 / 作成日：2026-09-20

本書は、今回作成したコードの設計と、当初要件から整理した完成時の設計案を区別して記載します。実装の根拠は `app/pilot.py`、検証の根拠は `app/TESTING.md` と `app/verification-status.json` です。要件の原文は同じフォルダーの `当初の実装要件.txt` に保存しています。

## 1. 目的と対象

Windowsで動く個人用のポケモンカード相場図鑑。日本の販売価格が50円以上のカードをパック別に収録し、日本の販売・買取価格と日本語版カードの米国未鑑定相場を比較する。所持枚数とメモを管理する。

完成時の技術構成はPython、SQLite、ローカルWebサーバー（FastAPI推奨）、ブラウザ画面。認証・複数ユーザー機能は不要。毎日午前2時の更新はWindowsタスクスケジューラで実行する予定。

## 3. 現行プログラムの構成

```text
コマンドライン
  ├─ demo        → 架空HTML
  ├─ import-html → 提供済みUTF-8 HTML
  ├─ discover    → カテゴリ候補取得
  └─ fetch       → 同一パックのページ取得
                         ↓
                  商品単位のHTML解析
                         ↓
                正規化・曖昧さの検出
                         ↓
              閾値判定 → SQLite保存
                         ↓
                  JSON結果・HTML確認表
```

| 主な処理 | 役割 |
|---|---|
| `Tree` / `Node` | 標準ライブラリHTMLParserで要素と親子関係を構築 |
| `parse_title` | 名前・レアリティ・型番・セットコードの解析 |
| `parse_products` | 商品リンクの親要素から価格・在庫を取得 |
| `discover_groups` | 実際に存在するproduct-groupリンクのみ抽出 |
| `paginated_urls` | 同じパックのpage指定リンクのみ採用 |
| `Client` | robots、アクセス間隔、上限、通信エラーの管理 |
| `store` | DB作成、初収録・更新、価格履歴保存 |
| `report_files` | 解析結果をJSONと静的HTMLに出力 |

実データ取得用ホストは `www.cardrush-pokemon.jp` に限定。HTTPSを使用し、`/phone/`、外部ホスト、認証情報を埋め込んだURLは受け付けない。外部画像URLを解析できても画像を取得・表示しない。

## 4. 解析と収録のルール

依頼文の `カード名(セット略称)【レアリティ】{型番} [セットコード]` を暫定的なタイトル形式とする。

- Unicode NFKCによる全角・半角統一を行う。
- レアリティは空白を除き大文字化し、生表記も保存する。
- `090/066` と `90/66` を同一の `90/66` にする。
- 名前の比較時は大文字・小文字、空白、句読点等を正規化する。
- 未知レアリティ、数値/数値以外の型番、状態・加工違い等は手動確認に回す。
- 商品領域の価格が複数ある場合、推測で価格を選ばない。
- 在庫0と在庫欠損を区別する。在庫0でも販売価格があれば価格履歴を保存する。
- 同一カードキーで内容の異なる商品がある場合は保存を保留する。
- カテゴリ内に複数セットコードがある場合は1パックと断定せず停止する。

**現行カードID**：パックID、正規化名、レアリティ、正規化型番を連結し、SHA-256の先頭24桁を使用する。パックIDは実取得時 `cardrush-{group-id}`、デモは `DEMO`。

初回の日本販売価格が50円未満なら収録しない。既存カードが50円未満になった場合は `is_active=0` に更新し、カード本体・所持情報・初収録日を保持する。50円以上に戻れば `is_active=1`。ページから見つからないことを値下がりや対象外の根拠にしない。

## 5. データベース設計

実際のDDLは `現行DBスキーマ.sql`。設計の説明よりこちらとコードを優先する。

| テーブル | 主な内容 |
|---|---|
| packs | パックID・名称・シリーズ・セットコード・発売日・カード数・出典 |
| cards | パック参照・名前・型番・正規化/元レアリティ・画像パス・出典・初収録日・対象フラグ |
| prices | カード参照・市場・売買区分・円換算値・元価格/通貨・為替・出典・日時・利用可否・在庫・実行ID |
| collection | カードごとの所持枚数・状態・メモ・更新日時 |
| runs | 実行ID・パックID・開始/終了日時・結果・取り込み方式・集計JSON |

現時点の価格はJP/sellのみ。実HTML取り込みはsource=`cardrush`、架空データはsource=`demo`として区別する。JPY価格のfx_rateは1。日時はUTC。保存済みHTMLでは元の取得日時が不明なため、取り込み日時を使用したことをレポートに明記する。

価格履歴検索用の複合インデックスを用意し、外部キーを有効化する。保存処理はトランザクションで実行し、接続を明示的に閉じる。通信やページ解析が途中で失敗した場合は保存処理へ進まない。

失敗はJSONレポートと通信ログに記録する。現行のrunsテーブルは保存に成功した実行を記録する構造であり、失敗パックの再試行キューはまだ存在しない。

## 6. 接続制御と現時点の障害

- User-Agent：`PokemonLocalCatalog/0.1 (personal collection; permission confirmed by user)`。
- 取得間隔は2秒。設定値の許容範囲は1〜3秒。
- 同一実行内の通信は最大40回、商品一覧は最大20ページ。
- robots.txtの取得失敗やHTML応答では許可とみなさない。
- robots.txtの待機条件が設定より長い場合も停止する。
- HTTP403/429を含むHTTPエラーで停止。自動再試行やリダイレクト追従は行わない。

2026-09-20、ユーザーの許諾確認済みとの指示を受けて接続した。robots.txtは200、PC版 `/group` は初回で403とCloudflare確認ページを返した。実商品0件、連続アクセス試験未実施。現在の障害は許諾の再確認ではなく、実データを取得できる接続方法が未確定なこと。

価格差の定義案は「米国円換算価格−日本販売価格」。差率はその差額÷日本販売価格×100とし、日本価格0以下なら算出不可。未取得の米国価格は一覧で「—」、詳細の価格差は「算出不可」。履歴不足時は「データ蓄積中」。これらの計算処理はまだ実装していない。
