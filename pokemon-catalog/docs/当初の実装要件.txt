# 実装プロンプト: ポケモンカード図鑑アプリ

このドキュメントは、AIコーディングエージェントにそのまま渡して実装を進めるためのプロンプトです。

---

## あなたへの指示

あなたはPythonエンジニアです。以下の要件に従って、Windows上で動くポケモンカード相場図鑑アプリを実装してください。**いきなり全体を作らず、必ずフェーズ1（1パックのパイロット実装）から着手し、動作確認が取れてから次のフェーズに進んでください。**

## 0. 前提・環境
- OS: Windows
- 言語: Python
- DB: SQLite
- 画面: ローカルサーバーを立ててブラウザで閲覧（FastAPI推奨。Streamlitでも可）
- 自動実行: Windowsタスクスケジューラで毎日午前2時に起動（Pythonスクリプトを直接叩く形でよい）
- 個人利用のローカルツール。認証・マルチユーザー対応は不要

## 1. アプリの目的
日本相場50円以上のポケモンカードを、パック別に一覧できる図鑑アプリ。日本相場（販売価格・買取価格）とアメリカ相場（日本語版カードの海外相場）を並べて表示し、所持管理もできるようにする。

## 2. データソースと取得方法

### 2.1 カードマスタ（名前・型番・レアリティ・画像）
- 一次情報源: 公式カード検索 `https://www.pokemon-card.com/card-search/`
- シリーズ（レギュレーション）で絞り込んで巡回する

### 2.2 日本相場（メイン）
- **cardrush-pokemon.jp のPC版URLを使うこと。`/phone/` が付いたモバイル版は使わないこと（JS描画で商品情報が取得できないため）**
- URLパターン: `https://www.cardrush-pokemon.jp/product-group/{id}`（末尾に `?page=2` 等でページング）
- 1つの`product-group/{id}`が1パック（またはレアリティ区分）に対応する。パックの新弾特集ページ（`https://www.cardrush-pokemon.jp/group`）や商品カテゴリ一覧ページから、対象となる全パックの`product-group`IDを洗い出すこと
- 各商品ページには「カード名(セット略称)【レアリティ】{型番}」の形式でタイトルがあり、価格・在庫数も同じ行に静的HTMLとして書かれている（実例: `ピカチュウex(30th)【SAR】{126/103} [M6a] 11,400円(税込) 在庫数 91枚`）。この形式をパースすること
- **実装前に必ず `https://cardrush.media/data_policy` の内容をブラウザで確認し、価格データの二次利用に関する規約に違反しないことを確認してから着手すること**
- リクエスト間隔は1〜3秒空けること。連続アクセスでブロックされないか、パイロット実装の段階で確認すること

### 2.3 日本相場（補完・裏取り）
- altema.jp/pokemoncard、snkrdunk.com/brands/pokemon
- cardrushで欠損したカードの補完、買取価格（altemaが言及する買取相場）の取得に使う

### 2.4 アメリカ相場（メイン）
- pricecharting.com（実体は sportscardpro.com）
- 日本語版セットごとに専用ページがある。URLパターン例: `https://www.sportscardpro.com/console/pokemon-japanese-{set-slug}`
- カードごとにUngraded/Grade9/PSA10の価格が掲載されている。**Ungraded（未鑑定）の価格をメインの参照値として使うこと**
- 英語のセット名表記（例: "Pokemon Japanese Web"）と、日本の正式パック名の対応表を作る必要がある。これは実装中に手作業でも構わないので早めに一覧化すること

### 2.5 アメリカ相場（補完）
- TCGplayer（`Pokemon Japan`ライン）。ただし日本語検索非対応、旧シリーズ非対応の可能性が高いので、現行〜比較的新しいシリーズの補完用として位置づける
- eBayは初期実装では対応不要

## 3. 同一カード判定ロジック（重要）
日本相場データと米国相場データを同一カードとして紐付ける際は、以下のキーが**すべて**一致した場合のみ紐付ける:
- キャラクター名
- レアリティ
- 型番（カード番号）

ただし比較前に正規化処理を行うこと:
- 全角/半角の統一
- 大文字/小文字の統一
- 記号・空白の除去やゆらぎ吸収（例: `090/066` と `90/66` を同一視）

3項目のうち1つでも一致しなければ、無理に紐付けず「データなし」として扱う。

## 4. データモデル（SQLite）

```sql
CREATE TABLE packs (
    pack_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    series TEXT,
    set_code TEXT,
    release_date DATE,
    card_count INTEGER,
    source_url TEXT
);

CREATE TABLE cards (
    card_id TEXT PRIMARY KEY,
    pack_id TEXT REFERENCES packs(pack_id),
    name TEXT NOT NULL,
    card_number TEXT,
    rarity TEXT,           -- 正規化済み
    rarity_raw TEXT,       -- 取得元の生表記
    image_path TEXT,       -- ローカル保存パス（直リンク禁止）
    source_url TEXT,
    first_listed_at DATE   -- 初めて日本相場50円以上として収録された日
);

CREATE TABLE prices (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    card_id TEXT REFERENCES cards(card_id),
    market TEXT NOT NULL,        -- 'JP' or 'US'
    price_type TEXT NOT NULL,    -- 'sell' or 'buy'
    price INTEGER,               -- JPY換算後の価格
    price_original REAL,         -- 元通貨での値
    currency TEXT,               -- 'JPY' or 'USD'
    fx_rate REAL,                -- 換算に使った為替レート
    source TEXT,                 -- 'cardrush' / 'altema' / 'snkrdunk' / 'pricecharting' / 'tcgplayer'
    fetched_at DATETIME NOT NULL,
    available BOOLEAN DEFAULT 1  -- 0の場合は「データなし」表示
);

CREATE TABLE collection (
    card_id TEXT PRIMARY KEY REFERENCES cards(card_id),
    owned_count INTEGER DEFAULT 0,
    condition TEXT,
    note TEXT,
    updated_at DATETIME
);
```

**収録ルール**: 一度「日本相場50円以上」として`cards`に収録されたカードは、その後相場が下がっても削除しない。50円未満に下がった場合は一覧表示上「対象外」フラグを立てるが、レコードは保持する（このフラグはcardsテーブルに`is_active`のようなカラムを追加して管理してよい）。

## 5. 画面仕様

### 5.1 画面一覧
1. パック一覧（トップ）
2. カード一覧（パック内）
3. カード詳細
4. 日米価格差ランキング
5. コレクション（所持カードのみ）
6. 設定・データ更新

### 5.2 カード一覧 — 表示モード切替（最重要機能）
ヘッダーに表示モードのトグルを置き、以下2モードを切り替えられるようにする。**選択状態はローカルに保存し、次回起動時も維持すること。**

**モードA: リスト表示（横1枚・縦に長く）**
1行1カードで、画像・キャラクター名・レアリティ・型番・日本相場（販売/買取）・アメリカ相場・価格差・所持チェックを表示。

**モードB: グリッド表示（横3枚・縦に連なる）**
3列グリッドで、画像・キャラクター名・レアリティ・日本相場・アメリカ相場を表示（型番は省略）。アメリカ相場が未取得の場合は「—」と表示する。

### 5.3 検索・絞り込み
- フリーワード検索（キャラクター名・型番）
- レアリティで絞り込み（複数選択）
- 価格帯で絞り込み（下限・上限）
- 所持／未所持で絞り込み
- 並び替え: 日本相場の高い順・安い順／型番順／価格差の大きい順

### 5.4 カード詳細
- 大きい画像、全項目（名前・レアリティ・型番・パック名・発売日）
- 日本相場（販売・買取）／アメリカ相場／価格差（米相場未取得の場合は「算出不可」と表示）
- 価格推移グラフ（履歴が溜まるまでは「データ蓄積中」と表示）
- 所持枚数の編集、メモ入力欄
- 取得元ページへのリンク

### 5.5 日米価格差ランキング
- 対象は全カード（下限フィルタなし）
- デフォルトの並びは「差額（円）」順。「差率（%）」順にも切り替え可能にする
- アメリカ相場が未取得のカードは対象外

### 5.6 データ更新
- 最終更新日時の表示
- 「今すぐ更新」ボタン（手動実行）
- 更新中は進捗表示（何パック中何パック完了か）
- 失敗したパックはログに残し、失敗分だけ再試行できるようにする

## 6. 非機能要件
- 一覧表示は仮想スクロール＋画像の遅延読み込みで、数千〜1万件規模でも操作感を保つこと
- 取得済みデータはオフラインでも閲覧できること
- 為替レート（USD→JPY）は日次取得し、換算に使ったレートを`prices.fx_rate`に保存すること
- 画像は必ずローカル保存すること（参照元への直リンクは禁止）
- DBファイルをエクスポートできる機能を用意すること（所持情報のバックアップ用）

## 7. 開発の進め方（フェーズ）

**フェーズ1: パイロット（最優先）**
1. cardrushの1パック分（`product-group`を1つ選ぶ）を対象に、取得→パース→SQLite保存までを通す
2. データが正しく取れているか目視確認する（レアリティ表記のゆれ、型番の欠損、価格・在庫のパース漏れがないか）
3. 連続アクセスに対する制限がないか確認する（このパイロットの中で数十リクエスト程度試し、ブロックされないか見る）

**フェーズ2: 画面の骨格**
4. カード一覧画面を作り、モードA/モードBの表示切替を実装する

**フェーズ3: 対象拡大**
5. 全パックのcardrush `product-group` IDを洗い出し、全パックに対象を広げる
6. 公式カード検索からカードマスタを補強する

**フェーズ4: 米国相場**
7. pricecharting.comの日本語版セットページから米国相場を取得し、同一カード判定ロジックで紐付ける

**フェーズ5: 機能拡充**
8. 検索・絞り込み、カード詳細画面
9. 所持管理、日米価格差ランキング

**フェーズ6: 自動化**
10. Windowsタスクスケジューラに毎日午前2時の自動更新を登録する

## 8. 注意事項・制約
- cardrush.media/data_policy の内容を実装前に確認し、規約の範囲内で取得を行うこと
- リクエスト間隔は1〜3秒空けること
- 取得した画像はローカル保存のうえ個人利用の範囲に留めること。第三者への再配布・商用利用はしないこと
- 各データソースの`robots.txt`を確認し、禁止されているパスにはアクセスしないこと
- 実装中に判断に迷った場合（レアリティ表記のゆれ、型番のない旧シリーズカードなど）は、無理に自動判定せず、ログに残して後で手動確認できるようにすること
