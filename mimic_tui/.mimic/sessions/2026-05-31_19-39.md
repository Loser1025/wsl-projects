## サブエージェントのコンテキスト分離ロジック

### 1. 全体構造

```
メインセッション（親エージェント）
  ├── コンテキスト A（会話履歴 + ツール結果）
  │
  ├── サブエージェント 1（フォーク）
  │     └── コンテキスト B（独立・分離）
  │
  ├── サブエージェント 2（フォーク）
  │     └── コンテキスト C（独立・分離）
  │
  └── サブエージェント N ...
        └── コンテキスト N（独立・分離）
```

### 2. フォークの仕組み

qwen-code では `forkedAgent.ts` でサブエージェントを生成します。

```typescript
// 概念的な流れ（qwen-code の実装を簡略化）

// 親エージェントがサブエージェントをフォーク
function forkSubagent(parentContext: Context, task: string): SubAgent {
  // ① 親のコンテキストを「浅いコピー」して引き継ぐ
  const childContext = {
    ...parentContext,
    // ただし会話履歴は空でスタート（これが分離の核心）
    conversation: [],
    // システムプロンプトはサブエージェント用に切り替え
    systemPrompt: getSubagentSystemReminder(task),
  };

  // ② サブエージェント専用のツールセットを制限
  childContext.tools = filterTools(parentContext.tools, ALLOWED_SUBAGENT_TOOLS);

  // ③ 独立したLLMクライアントとして動作
  return new SubAgent(childContext);
}
```

### 3. コンテキスト分離の核心ロジック

```typescript
// 分離のイメージ（擬似コード）

class SubAgent {
  private conversation: Message[] = [];  // ← 親とは完全に独立

  async run(task: string): Promise<string> {
    // ① タスクのみを最初のメッセージとして投入
    this.conversation.push({ role: "user", content: task });

    while (true) {
      // ② 自分のコンテキストだけでLLMを呼び出す
      const response = await llm.chat(this.conversation, this.tools);

      if (response.hasToolCalls) {
        // ③ ツール実行結果も自分のコンテキストにのみ追加
        const results = await this.executeTools(response.toolCalls);
        this.conversation.push(...results);
      } else {
        // ④ 最終回答を親に返す
        return response.text;
      }
    }
  }
}
```

### 4. 親への結果返却

```typescript
// 親エージェント側の処理

async function handleComplexTask(task: string) {
  // サブエージェントをフォーク
  const subagent = fork(this.context, task);

  // サブエージェントを実行（独立コンテキストで完結）
  const result = await subagent.run(task);

  // サブエージェントの「最終結果だけ」を親のコンテキストに追加
  // ← 中間のツール呼び出しや思考過程は親に伝わらない
  this.conversation.push({
    role: "assistant",
    content: `[サブエージェントの結果] ${result}`
  });

  // 親のコンテキストは「結果の要約」だけを受け取る
  // → 親のコンテキストを汚染しない
}
```

### 5. 具体的な分離メカニズム

| 要素 | 親エージェント | サブエージェント |
|---|---|---|
| 会話履歴 | 親の履歴を保持 | **空からスタート**（独立） |
| システムプロンプト | 親用プロンプト | サブエージェント専用プロンプト |
| ツールアクセス | 全ツール | **制限されたツールセット** |
| LLM コンテキスト窓 | 親の消費量 | **独立した消費量** |
| 中間結果 | 親が見る | 親には**最終結果のみ**伝達 |

### 6. なぜこれが性能に効くか

```
【従来の単一エージェント（MimicTUI方式）】
タスク開始 → ツール1 → ツール2 → ツール3 → ... → 回答
              ↑ 全ツール結果が親のコンテキストに蓄積
              ↑ コンテキスト窓を急速に消費
              ↑ 圧縮が頻発 → 情報損失 → 性能低下

【サブエージェント分離（Qwen-Code方式）】
タスク開始
  ├─ サブ1: ツール1 → ツール2 → 結果A  ← サブ1のコンテキストで完結
  ├─ サブ2: ツール3 → ツール4 → 結果B  ← サブ2のコンテキストで完結
  └─ 親: 結果A + 結果B → 最終回答      ← 親は結果だけ受け取る
       ↑ 親のコンテキストは最小限
       ↑ 圧縮不要 → 情報損失なし → 高性能
```

### まとめ

サブエージェントのコンテキスト分離とは、**「親エージェントの会話履歴をサブエージェントにコピーせず、サブエージェントは空の状態からタスクを実行し、最終結果だけを親に返す」** という設計です。これにより：

1. **親のコンテキスト窓を消費しない** → 長文タスクでも圧縮が不要
2. **各サブエージェントが独立したコンテキストで動作** → 並列実行が可能
3. **中間のツール呼び出しや思考過程が親に伝わらない** → ノイズが混入しない

MimicTUI にはこの仕組みがなく、全ツール呼び出しが単一の `self.conversation` に蓄積されるため、複雑なタスクではコンテキスト超過 → 圧縮 → 情報損失 → 性能低下という連鎖が起きやすくなります。
