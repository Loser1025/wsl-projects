📖 概要

mimic_tuiは、マルチモード動作とマルチエージェント協調によるAI支援開発環境です。

🎯 核心概念

マルチモード: ReActモードとPlan-and-Executeモードの切り替え

マルチエージェント: 3つの専門エージェントによる協調作業

動的ワークフロー: 条件分岐・ジャンプ・並列実行をサポート

📁 主要コンポーネント

main.py: メインループ・モード管理

orchestrator.py: ワークフロー制御

multi_agent.py: マルチエージェントシステム

architect_agent.py: エージェント定義・比較

🎨 アーキテクチャ

基底クラス: RoleAgentBase

実装エージェント: Architect, Operator, Scribe

協調層: MultiAgentOrchestrator

ワークフロー層: WorkflowGraph

🎯 動的ルーティング機能

条件分岐

on_failure: retry, skip, abort, goto:<label>

on_success: "" (次へ), goto:<label>, abort

最大リトライ: 2回

ループ防止

max_iterationsでgotoループの上限を設定

デフォルト上限: 10回

上限超過時: 自動的にskipに格下げ

共有ステート

形式: [STATE: key=value]

自動パース: parse_state_updates()

ステート種別: changed_files, test_command, last_error

⚡ 並列実行

parallel: trueが設定されたステップは、前後の同種ステップと並列実行されます。

join_policy:

  • all (デフォルト): 全ステップ完了を待つ
  • any: いずれか1つ成功した時点で次へ進む
  • first: 最初に完了したステップの結果で次へ進む

並列数制限: RPM（Request Per Minute）に基づいて自動調整

🏆 総合評価: ★★★★☆

✅ メリット

  1. 役割分離の徹底: 各エージェントの責任範囲がツール・行動指針・協調ステップの3層で明確化
  2. 協調メカニズム: MultiAgentOrchestratorによるステップごとの成否判定とルーティング
  3. 拡張性: RoleAgentBaseを継承する設計により、新たな役割エージェントの追加が容易
  4. 動的ワークフロー: 条件分岐・ジャンプ・並列実行・ステート管理を統合
  5. モード柔軟性: ReActモードとPlanモードのシームレスな切り替え

❌ デメリット

  1. 依存性: Architectの出力にOperatorが依存（報告フォーマットが崩れると全ワークフローが停止）
  2. 柔軟性の低さ: 固定されたステップにより、動的なタスクへの対応が制限
  3. 学習コスト: 3つのエージェントの役割と協調メカニズムを理解する必要
  4. リソース消費: 複数エージェントの同時実行によりAPIコストが増加

🎯 総合評価と改善提案

🌟 総合評価: 4.5/5.0

マルチモード動的ワークフローとマルチエージェント協調を統合した、非常に洗練されたシステムアーキテクチャ。

✅ 成功要因

1. アーキテクチャの明快さ

RoleAgentBaseを基底クラスとした継承設計により、コードの再利用性と拡張性を両立。

利点: 新たな役割エージェントの追加が容易

2. ワークフローの柔軟性

WorkflowGraphによる動的ルーティングにより、線形だけでなく条件分岐・ジャンプ・並列実行をサポート。

利点: 複雑なタスクにも対応可能

3. 協調メカニズムの堅牢性

MultiAgentOrchestratorによるステップごとの成否判定と自動ルーティング。

利点: エージェント間の依存関係を明確化

4. モードの多様性

ReActモードとPlanモードのシームレスな切り替えにより、タスクの性質に応じた最適なアプローチを選択可能。

利点: ユーザーの作業スタイルに適応

💡 改善提案

  1. Architectのテスト設計支援

    テストコマンドの自動生成や妥当性チェックを追加し、Operatorへの依存を軽減。

    期待効果: ワークフローの信頼性向上

  2. Scribeの自動圧縮

    コンテキスト長が閾値を超えた場合に自動でcompact_memoryをトリガー。

    期待効果: 記憶管理の自動化

  3. ワークフローの動的最適化

    タスクの複雑さに応じて、ステップの並列実行やスキップを許容。

    期待効果: 処理効率の向上

  4. エラーハンドリングの強化

    Architectの出力フォーマットが崩れた場合のフォールバックメカニズムを追加。

    期待効果: システムの堅牢性向上

  5. リソース管理の最適化

    並列実行数をRPM（Request Per Minute）だけでなく、タスクの優先度でも制御。

    期待効果: APIコストの最適化
